# PEC computational reproducibility record

Release: `pec-prospective-2026-08-09-r9`

## What has been completed

The release validator has been executed with a clean temporary-directory rerun.
It independently copies the declared inputs, regenerates every JSON and CSV
output, compares regenerated bytes with the deposited outputs, and verifies
every file listed in `release-manifest.sha256`.

Run:

```bash
python scripts/validate_repository.py --rerun
```

The expected terminal result is:

```text
[OK] PEC prospective release validation passed.
```

```bash
python -m pec_model.mortality_near_term
python -m pec_model.mortality_mature
python -m pec_model.economic
```

They regenerate the mortality and economic JSON/CSV outputs in `results/`.
The environment used for the archived run is recorded in
`docs/software-environment.txt`.

## Deployment-data readiness check

The prospective validation data specification can be checked without outcome
data:

```bash
python scripts/validate_deployment_export.py --schema-only
python scripts/test_deployment_validator.py
```

After a future trial exports the seven prescribed CSV tables, run:

```bash
python scripts/validate_deployment_export.py --data-dir PATH_TO_EXPORT
```

This checks required columns, primary keys, episode foreign keys, enumerated
values, function numbers, numeric ranges, and timestamp ordering. Passing it
establishes structural data readiness, not a PEC causal effect.

## Scope of the claim

Completed internal clean-room reruns establish computational reproducibility of
the deposited implementation. They do not validate the interim priors, establish
empirical transportability, or substitute for independent external statistical
reproduction. Independent reproduction and deployment-based validation remain
open gates and must be reported as pending until performed by parties outside
the modeling team.
